# โปรเจกต์ Alpha — บริษัท เอ็นพีซี จำกัด

> เอกสารสมมติสำหรับ demo (ข้อมูลภายใน — ตัวอย่างข้อมูลลูกค้า/โปรเจกต์)

## ข้อมูลลูกค้า
- ลูกค้า: บริษัท สยาม รีเทล กรุ๊ป จำกัด (Siam Retail Group)
- ผู้ติดต่อหลัก: คุณวิไล (ผู้จัดการฝ่ายไอที) โทร 02-xxx-xxxx
- ประเภทงาน: พัฒนาระบบ POS และแอปสะสมแต้มสำหรับร้านค้าปลีก 120 สาขา

## สถานะโปรเจกต์
- ระยะ: Phase 2 (พัฒนาโมดูลสะสมแต้ม) — คาดส่งมอบ Q3/2567
- Project Manager ฝั่ง NPC: คุณกิตติ
- ทีม: dev 4 คน, QA 1 คน, designer 1 คน

## ประเด็น/ปัญหาที่เคยเจอ (lessons learned)
1. Phase 1: ระบบ POS มีปัญหา sync ข้อมูลตอนสัญญาณเน็ตร้านสาขาหลุด → แก้โดยเพิ่ม offline queue
2. ลูกค้าขอเปลี่ยน scope กลางทาง (เพิ่มรายงานยอดขายรายสาขา) → ทำ change request เพิ่มงบ 15%
3. การส่งมอบ Phase 1 ล่าช้า 2 สัปดาห์เพราะรอ UAT จากฝั่งลูกค้า → Phase 2 กำหนด UAT window ชัดเจนในสัญญา

## ข้อควรรู้เมื่อคุยกับลูกค้ารายนี้
- ลูกค้าให้ความสำคัญกับ uptime มาก (SLA 99.5%)
- ต้องส่งรายงานความคืบหน้าทุกวันศุกร์
- การเปลี่ยน scope ทุกครั้งต้องทำเป็นลายลักษณ์อักษร (change request) เท่านั้น
